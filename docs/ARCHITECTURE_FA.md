# معماری PVNetwork

هدف این پروژه ساخت یک کلاینت عمومی و مرجع است؛ بنابراین رابط کاربری نباید به یک موتور یا یک پروتکل خاص وابسته باشد.

## لایه‌ها
`UI -> ConnectionManager -> ProtocolRegistry -> ProtocolAdapter -> Engine -> Android VPN API`

### UI
صفحه خانه، افزودن کانفیگ، QR، سرویس‌های PVNetwork، حساب و تنظیمات.

### ConnectionManager
وضعیت اتصال را مدیریت می‌کند و Adapter مناسب را انتخاب می‌کند.

### ProtocolRegistry
لیست قابلیت‌های فنی را نگه می‌دارد و از نام دسته‌بندی تجاری جدا است.

### ProtocolAdapter
کانفیگ نرمال‌شده را به ورودی موتور مربوط تبدیل می‌کند.

### Engine
در مراحل بعدی موتورهای لازم مثل Xray/sing-box، OpenVPN، WireGuard، OpenConnect و IPsec با بررسی دقیق لایسنس اضافه می‌شوند.

## قواعد غیرقابل نقض
- دسته‌بندی فروش، تعداد سرور و قیمت داخل اپ هاردکد نمی‌شود.
- کاربر عمومی بدون لاگین می‌تواند کانفیگ خودش را وارد کند.
- Credential مدیریتی پنل‌ها هرگز داخل کلاینت قرار نمی‌گیرد.
- کانفیگ خصوصی کاربر به‌صورت پیش‌فرض Local-only است.
- هر پروتکل جدید باید از طریق Adapter اضافه شود، نه با تغییر UI اصلی.
